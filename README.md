# AI Answer Share Lab

**Live demo:** https://yashsarkar1806-creator.github.io/ai-answer-share-lab/?demo=1

More buyers now start with “what’s the best tool for…” in an AI assistant instead of a search engine. If the assistant names three competitors and not you, you never get to make your case. **AI Answer Share Lab** is an in-browser toolkit for measuring that, sometimes called generative engine optimisation (GEO) or AI search visibility.

Paste in the answers you collected from the AI assistants you track and get:

- **A brand scorecard**: mention rate (with a 95% Wilson interval), how often each brand is named first, average rank, plain share of voice and **position-weighted share of voice** (first brand named = 1 point, second = ½, third = ⅓…).
- **Engine and buying-stage heatmaps**, so you can see, for example, that you show up for use-case prompts but disappear on “which is most trusted?”.
- **Prompt gaps**: prompts where competitors are named and you aren’t, ranked by severity, along with the sources cited in those answers.
- **A source leaderboard** of the domains the engines cite, split by whether your brand appeared. A review site cited mostly in answers *without* you is a PR or listing target.
- **Trend between snapshots** with a two-proportion z-test, so a jump from 39% to 56% on 36 answers is flagged honestly as “not yet significant”.
- **Tone around mentions**: a simple positive/negative word list applied to the sentences that name each brand (a rough signal, not a sentiment model).
- **A prompt-panel generator** that writes a buying-journey prompt set (discovery, comparison, problem, trust, use case) and a CSV template to fill in.
- **An answer explorer** with brand names highlighted, a filter for “answers missing my brand”, a copyable plain-English readout and a per-answer CSV export.

Everything runs client-side with no build step and no API keys. No data leaves the browser.

## Why I built it

Brand and growth teams already track search rankings and share of voice in ads and social. AI answers are a new shelf, and most teams don’t measure it yet. This is how I would approach it as a marketer: fix a prompt panel that mirrors the buying journey, measure where the brand is missing, find the sources the engines trust, then act (comparison and use-case pages, review-site listings, PR) and re-measure on the same panel.

## Demo data (synthetic)

`data/murmur-synthetic-ai-answers.csv` holds 72 **synthetic** answers: 12 prompts × 3 engines × 2 snapshot dates for a **fictional** AI meeting note-taker, “Murmur”, and three fictional competitors (Notewise, Scribbly, TalkTrail). The engines are labelled “Assistant A/B/C”, and every cited domain uses the reserved `.example` TLD. The file is generated by `scripts/generate-demo.mjs` (seed `20261113`). None of it is real output from a real AI product, and no real company or employer is involved.

## Use your own answers

1. Generate a prompt panel in the app (or write your own) and download the CSV template.
2. Run each prompt in the assistants you track, ideally more than once, and paste each answer into the `answer` column, sources included.
3. Paste or upload the CSV, list your brands, and press **Analyse**.

| Column | Meaning |
| --- | --- |
| `prompt` | Required. The question you asked (`query` / `question` also work). |
| `answer` | Required. The full answer text, including any links (`response` / `output` also work). |
| `engine` | Optional. Which assistant answered (`model` also works). |
| `intent` | Optional. Buying stage, e.g. Discovery, Comparison, Trust. |
| `snapshot` | Optional. Date or label of the collection run (`date` / `week` also work). The latest snapshot is analysed and compared with the previous one. |

Brands go one per line: `Name | alias one, alias two | own`. Matching is whole-word and case-insensitive, so “Acme” won’t match “Acmeville”.

## Limits

- AI answers vary between runs, days and accounts. Use several runs per prompt and keep the panel fixed between snapshots.
- Mention detection is string matching on names and aliases, so add common misspellings as aliases.
- Tone is a word-list heuristic. Read the highlighted answers before quoting it.
